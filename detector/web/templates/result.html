{% if report.wire_api in ['interactions', 'generate_content'] %} Gemini 原生检测项各自检查什么?
基础回复
发送随机校验文本，检查接口完整响应与指定内容。
流式完整性
检查所选原生接口的事件顺序、文本增量和正常结束状态；错误、中途断流或未结束的内容不能通过。
结构化输出
以原生 JSON Schema 参数提交，验证返回值、字段和随机校验内容。
工具调用往返
验证函数名和参数，保留原始签名历史回传本地随机回执；不执行外部工具。
{% elif report.wire_api == 'responses' %} Responses 检测项各自检查什么?
基础回复
发送带随机校验文本的 Responses 请求，确认完整响应能准确返回本次指定内容。
流式完整性
检查 Responses 类型化事件、文本增量、响应与消息 ID、结束事件是否相互一致；中途断流或错误不能通过。
结构化输出
通过 text.format 请求严格 JSON Schema，检查字段、类型和随机校验值。标准和完整档执行。
工具调用往返
请求本地模拟函数，校验参数后回传对应 call_id 的随机回执，再检查最终回答。仅完整档执行，不执行模型生成的代码或外部工具。
检测边界
未选中的项目显示未测试。这些结果说明本次接口能力，不能证明模型身份、实际扣费或长上下文能力，也不参与公共榜单评分。
{% elif protocol == 'openai' %} OpenAI 检测项各自检查什么?
基础请求 (Basic Request)
发送最小 Chat Completions 请求,确认接口可用且能提取 assistant 文本。
模型一致性 (Model Consistency)
验证 response.model 与请求模型匹配,并检查低温多次调用的输出 token 稳定性。
函数调用 (Function Calling)
强制 tool_choice,验证 call_ ID、type=function、函数名和 arguments JSON。
结构化输出 (Structured Output)
使用 response_format=json_schema,检查返回内容能否按 schema 解析。
协议规范性 (Protocol)
被动检查 chatcmpl- ID、chat.completion、choices、finish_reason、usage 等官方字段。
流式一致性 (Integrity)
比较同一 prompt 的 stream 与 non-stream 文本、finish_reason 和 usage 是否一致。
Token 计费
检查中转站返回的输入/输出 Token 数是否自洽,并和同一次检测里的流式/非流式结果、本地可预期的变化进行对比。
长上下文真实性 (Long Context)
需在提交时勾选启用 — 用 needle-in-haystack 在 32k → 100k → 200k tokens 三档探针,验证中转站是否真兑现宣传的 context window(识别截断 / 路由到小窗口模型)。极限档可按模型完整上限自适应探到 950k+。
{% elif protocol == 'gemini' %} Gemini 检测项各自检查什么?
基础请求
发送 Chat Completions 请求，确认兼容接口可用且能提取文本响应。
模型响应形状
检查兼容响应中的 model、choices、finish_reason 等字段。
函数调用
通过 OpenAI 兼容接口发起工具调用，检查函数名、参数和结束原因是否符合请求。
结构化输出
通过兼容接口请求 JSON 输出，检查内容能否解析并满足指定结构。
协议规范性
检查 OpenAI 兼容响应的字段与类型；本入口不检测 Gemini 原生 API。
流式一致性
比较同一 prompt 的流式与非流式兼容请求，复核文本、结束原因和用量字段差异。
Token 用量
检查兼容响应的 usage 是否完整、统计是否自洽，以及长短文本的 Token 增量是否合理。
{% else %} 12 项检测各自检查什么?
身份一致性 (Identity)
记录模型自述与关键词偏差。回答可能受提示词或托管环境影响，不能据此确认身份。
行为签名验证 (Behavioral)
用固定问题观察格式、列表与拒绝行为。风格可被模仿，也会随模型版本变化，只作为复核线索。
思维签名验证 (Thinking) ⭐
核心检测:先回传原始 thinking block,再篡改一个签名字节做负向对照;只有原始请求成功且篡改请求被明确拒绝才通过。
模型一致性 (Consistency)
验证 response.model 与请求一致,且多次调用输出长度稳定(变异系数 CV)。
知识准确度 (Knowledge)
用固定知识问题检查本次回答；知识错误、信息过时或答题风格都不能单独证明换模。
PDF 文档识别
提交含指定字符串的 PDF，检查本次能否提取。失败可能来自格式、权限、代理实现或模型能力，应结合错误详情复核。
结构化输出 (Tool Use)
真实 tool_use 调用,验证 toolu_ ID 前缀、JSON schema 匹配、stop_reason 等 5 项子项。
协议规范性 (Protocol)
SSE 事件序列、content block 类型必须符合 Anthropic 官方规范(被动检测,不发额外请求)。
响应完整性 (Integrity)
同一 prompt 流式与非流式调用必须返回一致的文本、input_tokens、stop_reason。
Token 用量
检查 Claude Messages 的 usage.input_tokens/output_tokens 是否存在、长短 prompt 增量是否合理、短输出是否没有超报,并用 stream 与 count_tokens 做交叉验证。
消息标识规范 (Message ID)
检查消息 id 和工具 ID 的格式。偏差说明接口实现不同；符合格式也不能证明模型身份。
长上下文真实性 (Long Context)
需在提交时勾选启用 — 用 needle-in-haystack 探针检查不同长度输入的响应表现。失败可能来自截断、额度、超时或入口限制，不能据此确认模型身份。Anthropic 路径用 count_tokens 端点预算 token；极限档参考模型目录中已核对的输入上限。未覆盖的长度不作结论。
